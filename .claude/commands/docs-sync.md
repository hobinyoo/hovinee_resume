# 문서 동기화

현재 코드 상태와 문서가 일치하는지 확인한다. **잘못된 것만** 플래그하고, 문서를 위한 문서는 만들지 않는다.

## 지침

1. **최근 코드 변경 사항 찾기**:
   ```bash
   git log --since="30 days ago" --name-only --pretty=format: -- "*.ts" "*.tsx" | sort -u
   ```

2. **동기화 대상 문서 확인** (이 템플릿의 "살아있는 문서"):
   - **`CONVENTIONS.md`** — 규칙 단일 진실원. 코드가 규칙과 어긋나거나, 규칙이 실제 관행과 어긋나면 플래그.
   - **`AGENTS.md`** — 스택·환경변수·배포·아키텍처 결정이 코드 현실과 맞는지.
   - **`.claude/CLAUDE.md` / `.claude/README.md`** — 요약·구조 설명이 최신인지.
   - `/docs/` · 변경된 코드 근처 README · 변경 파일의 TSDoc 주석.

3. **문서 정확성 검증**:
   - 코드 예시가 여전히 동작하는가?
   - API 시그니처·prop 타입이 최신인가?
   - 경로/디렉토리 설명(`src/routes/`, `features/` 등)이 실제 구조와 맞는가?
   - 환경변수 목록(`VITE_*` 등)이 실제 사용과 일치하는가?

4. **실제 문제만 보고**:
   - 문서는 살아있는 문서 — 틀린 것만 플래그, 단순 누락은 제외.
   - 규칙 변경이 필요하면 "코드가 아니라 `CONVENTIONS.md`를 먼저 고친다" 원칙을 상기.

5. **업데이트가 필요한 문서 체크리스트 출력** (파일:라인 + 무엇이 어긋났는지 + 수정 방향).
